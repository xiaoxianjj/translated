# Windows 生命周期与设置稳定性修复

本次修复对应整体检查中的四项问题，位于本地 `fix/windows-lifecycle-stability` 分支。

## 退出崩溃

使用本机 DAC 离线读取已有崩溃转储，调用栈落在 `Marshal.FreeHGlobal`。将栈中的托管方法 token 与当时保留的可执行文件对应后，得到：

```text
Program.Main
  ApplicationContext.Dispose
    TranslatorApp.Dispose
      InputWindow.Dispose
        Marshal.FreeHGlobal / LocalFree
```

最小程序验证了退出顺序：`Application.Run(context)` 返回时已调用一次 `Dispose(true)`，外层 `using` 又调用一次。旧输入监听器每次都释放同一个原生缓冲区，形成重复释放。修复为应用与监听器的幂等清理，并在释放缓冲区时清空指针、阻止已释放监听器继续处理输入消息。此实现也符合 [ApplicationContext.Dispose 对派生类的要求](https://learn.microsoft.com/dotnet/api/system.windows.forms.applicationcontext.dispose)。

最终退出回归还捕获了取词延时在消息循环结束后返回的异步竞态。选区按钮探测现由可取消任务管理，退出时先取消并等待探测任务及原有任务／剪贴板清理，再结束消息循环。前台切换改为复用卡片定时检查，不额外留下异步延时回调。

转储及调试组件仅用于本地分析，不随软件分发；分析日志不包含翻译原文或凭据。

## 关闭卡片

关闭按钮、Esc、Alt+F4 和标准 `Window.Close` 统一走卡片关闭入口：取消请求、停止检查、隐藏卡片、清空会话并撤销临时置前。软件退出时的销毁不再重复发出用户取消操作。

## 配置快照

新任务创建时复制服务名称、地址、模型、推理开关、是否已配置及简繁体偏好，目标语言仍由任务自身保存。排队期间保存其他设置不会再改变已有任务的服务或输出偏好。密钥按任务固定的服务地址读取，不复制到设置快照；自动交付仍按当时的安全条件检查，避免忽略用户在翻译期间关闭替换的操作。

## 高缩放与小工作区

快捷键编辑器按所在显示器的工作区与 DPI 限制尺寸，同时降低超出工作区的最小尺寸。内容区可滚动，保存和取消按钮固定在底部；监视器 DPI／工作区变化后重新适配并限制窗口位置。较早的 Windows 10 使用监视器 DPI 兼容路径。

## 验证

- 应用与 net48 测试构建通过，0 警告、0 错误。
- 32 项核心检查分别在 net48 和 net8.0 通过。
- 12 项无可见窗口专项检查通过：实际翻译方法的固定配置路由、标准关窗取消、销毁关闭行为、四种工作区布局和五轮实际 WinForms 消息循环退出／重复清理。
- 布局检查包括 960×520、1092.8×582.4、640×340 DIP；保存按钮拥有实际可点击尺寸且位于可见区域。生成的布局图已检查。
- 未自动操作浏览器、未发送桌面测试按键、未调用付费服务。真实显示器之间拖动的完整交互尚未实机验证。
